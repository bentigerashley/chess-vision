Chess Vision Capture Direction

Created: 2026-07-17

Grounding context

The rebuilt repository is a React PWA with an editable board, optional browser model seam, local Stockfish 18 lite single-thread assets, and a Three.js dataset studio. The user has authorised removal of the original Android project and delegated remaining product decisions.

Candidate directions

  1. Correction-first calibrated scanner — recommended

    Before inference, the player marks the four board corners and confirms which side is white. The app rectifies the board, classifies 64 squares with a versioned TensorFlow.js model contract, highlights uncertainty, and always sends the player to the editable board.

    Why it wins: it closes the image-to-model gap without betting the first release on unreliable automatic board detection, and the same geometry produces usable synthetic labels.

  2. Full-board detector

    Train a single model to return all 64 pieces and board geometry directly from an arbitrary image. This is the lowest-friction player flow but needs considerably more labelled real-world data and a more complex evaluation pipeline.

    Rejected for now: it makes the first model and training requirements too broad.

  3. Manual board only

    Keep photo import as reference imagery and have the player construct the position by hand. It is robust but loses the key differentiation of chess vision.

    Rejected: it does not advance the requested ML-assisted capture experience.

Chosen design constraints

  • Inference consumes 64 rectified 224×224 RGB square crops, normalized to [0,1], and returns 13 logits per crop.
  • Model metadata declares class order, crop size, orientation, and contract version; absent or incompatible metadata routes to correction-only mode.
  • Every synthetic sample includes board-corner coordinates, per-square polygons, 64 square labels, FEN, side to move, and render seed.
  • Castling rights and en passant default to none and are visibly labelled as conservative assumptions until editable position-details controls are added.
  • Stockfish uses the pinned lite single-thread WebAssembly build, requests up to three variations at a bounded depth, and reports unavailable or terminal-position states without losing board edits.

Rejected scope

Automatic board detection, account features, cloud training, and native wrappers remain deferred.
